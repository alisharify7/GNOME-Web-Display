# GNOME Web Display v2.0.0

## Interactive installation, version selection and a cleaner project

Start from one terminal command, choose a published version, and let the installer
guide you through source verification, dependency checks, setup and startup:

```bash
curl -fsSL https://raw.githubusercontent.com/alisharify7/GNOME-Web-Display/main/install.sh | bash
```

This command requires the new installer to be published on main. The v2 series
becomes selectable once the v2 tag is pushed.

### New installer

- Fetch available version tags from Git; choose an exact tag, `v1`, `v2` or `latest`.
- Use a menu for the complete workflow, verify-only, setup-only, start-only or
  clone-only. Interactive prompts work when invoked through a shell pipe.
- Verify the selected tag/commit and source files before executing setup/start.
  Missing dependencies can be repaired by setup; failed final checks block startup.
- Keep versions in separate directories, reuse clean installs and preserve private
  settings. Dirty checkouts and moved tags are rejected instead of overwritten.
- Keep `--yes` opt-in; do not run the installer as root or install autostart services.

### Organized source tree

Python lives in `src/gnome_web_display/`, the frontend in `web/`, shipped configuration
in `config/`, and shell implementations in `scripts/`. Root start/setup/run entry
points remain available. `VERSION` now supplies the application's version directly.

### Migration

Stop the old live session first because media ports are shared. Install v2 in a
new directory and copy only the settings/secrets you intend to reuse. Root private
`config.toml` and existing `VSCREEN_*` environment variables remain supported; the
example file moved to `config/config.example.toml`.

### Validation and scope

See `docs/TESTING.md` for the executed application, local Git installer, terminal,
HTTP/demo and UI checks. Real GNOME capture, physical-device input/audio, Docker
media delivery, APT installation and public GitHub download/install remain subject
to host/deployment validation. No performance or security certification is claimed.

Checksums and pinned Git object comparisons detect inconsistencies; they are not
an independent publisher signature. Use trusted source and trusted networks.
